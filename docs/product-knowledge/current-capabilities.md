# Vecmo Current Capabilities

Created: 2026-06-22.

The source-grounded inventory of what Vecmo can do **today, in this checkout**.
Every entry is grounded in actual `src/` / `worker/` wiring — a route, tool
registry binding, keyboard shortcut, panel control, or menu item that reaches a
handler. Beta entries may still need manual browser/export smoke before release;
per-feature docs call out skipped verification. Planning docs under `docs/*.md`
describe a larger roadmap; they were **not** treated as evidence and are not
reflected here.

Use this page to answer: *what can a user actually do, where, and what is still
limited?* Each table lists a capability, its status, what you do (with the
affordance — shortcut, panel, or menu — woven in), and the primary source file.
Per-category **Limits** bullets follow each table; everything that exists in code
but is not reachable is collected in [Not yet reachable](#not-yet-reachable).

## Status key

| Status | Meaning |
| --- | --- |
| `public` | Finished, end-user-facing, works in this build with no setup. Safe to describe outward. |
| `beta` | Works but partial, evolving, or gated on production provisioning that this checkout can't verify. Describe with caveats. |
| `internal` | Developer / operator / agent tooling, not part of the end-user editor product. |
| `draft` | Placeholder content that is explicitly not final (legal templates). |

> Vecmo as a whole is pre-launch. `public` means "an editor capability that works
> for a user in this build," not "commercially released." The browser editor runs
> offline; the commercial backend (auth, checkout, billing, admin) is built but
> unprovisioned.

**Limits.** Browser-local persistence supports multiple independent Working
Copies but remains local to the browser profile. Cloud projects are explicit
save/open plus one-writer active-project autosave with recovery-first conflict
actions, not live sync, shared cursors, or semantic merge.
Version restore advances a new current revision rather than mutating historical
rows. `/projects` is a focused open/recovery surface rather than a generic file
manager. Cloud writes are capped at 20 active projects, 200 revisions per
project, and 1 GB of saved
revision bodies per personal workspace for MVP cost safety. Inspector toggle is
`Mod+⌥+P`, not `Mod+⌥+I` (DevTools chord).
Parameter Capture Stage is a filmed overlay only; it does not yet record/export
the HUD or save capture presets. iPad canvas authoring mode still needs a
TestFlight-installed physical-device pass before it can be treated as finished.
Visual Review remains beta until browser/GPU/4K smoke is authorized; it does not
persist review pixels or verdicts, auto-score aesthetics, or guess ambiguous
diagnostic owners. Grain-off is optional rather than a completeness condition.
Cloud recovery from the iPad quickbar opens the existing `/projects` recovery
surface rather than an in-canvas revision browser. Native Pencil squeeze depends
on the iPad shell bridge and falls back to the web quickbar Quick Menu when the
bridge is unavailable.

controls. Polygon/star are wired through the desktop Shape flyout, shortcut
cycle, and iPad Quick Menu while the Shape tool is active. Blend currently accepts two or more
visible, unlocked, same-layer, same-artboard, leaf vector sources; matching
editable geometry stays parametric unless explicit source anchors define contour
correspondence, while mixed primitives and mismatched simple paths generate
sampled path-morph intermediates per adjacent source stop.
The Blend tool
hit-tests source anchors/endpoints ahead of object bodies within the handle
radius, previews candidate anchors on hover, and stores the clicked point as
that source's registration; open-spine endpoint drags and Replace Spine move
sources by their registration point. Selecting a Blend plus one top-level
same-layer line, path, or shape can replace the Blend spine; generated steps can
keep page orientation or align to the spine tangent, and the Blend tool can drag
spine endpoints, straight/path spine segments, path anchors, and visible tangent
handles directly on the canvas. Closed spines behave as contour/distribution
spines, so their anchors edit the loop without moving both source endpoints to
the same seam. Clicking a straight or path spine segment inserts a new anchor and
promotes straight spines to editable open paths; clicking a spine handle gives it
an active sub-selection, Delete/Backspace resets selected tangent handles, and
Delete/Backspace removes selected valid path spine anchors while keeping
open-path endpoint anchors protected. Compound paths blend:
outer contours pair directly, holes pair greedily by bounds-relative centroid
(a donut morphs into a donut), and an unmatched hole closes or opens in place
as a point; generated compound steps render even-odd so aligned contours stay
holes. It excludes
text, images,
frames/components, existing blends, effects, vec-core looks, compound paths
beyond 16 contours, mesh
paints, and image-reference paints. The Frame tool creates artboards (drag or
click for a preset) but does not move/resize existing ones — that stays on
Select.
